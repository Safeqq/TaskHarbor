# Phase 9 benchmark

This report records one local run measured on 2026-09-21 at 11:50:04 UTC. It is evidence for the tested workload, not a capacity target or service-level promise. The benchmark used commit `0ba19104a3d7fcf9c3b61de3caf2d86d3638365b` plus the uncommitted Phase 9 working tree; the generated JSON correctly reported `git_worktree_dirty: true`.

## Results

| Measurement | Count | Minimum | p50 | p95 | Maximum | Mean |
|---|---:|---:|---:|---:|---:|---:|
| API submission latency | 12 | 65.14 ms | 274.57 ms | 287.68 ms | 287.68 ms | 239.74 ms |
| Queue wait | 12 | 37 ms | 533 ms | 1,164 ms | 1,164 ms | 609.17 ms |
| Image decode, resize, JPEG encoding, and output write | 12 | 205 ms | 222 ms | 229 ms | 229 ms | 218.42 ms |
| Complete worker attempt | 12 | 329 ms | 340 ms | 352 ms | 352 ms | 342.17 ms |
| Submission start to terminal job state | 12 | 497 ms | 1,151 ms | 1,795 ms | 1,795 ms | 1,196.58 ms |

The API accepted the burst at 14.41 jobs per second over an 832.97 ms submission window. All 12 jobs succeeded; failed and cancelled jobs were zero, giving a measured failure rate of `0.0` for this run.

Peak working set, sampled every 100 ms with `Get-Process.WorkingSet64`, was 19,619,840 bytes (18.71 MiB) for the API and 69,099,520 bytes (65.90 MiB) for the worker process.

For this workload, queue wait was the largest measured part of p95 end-to-end latency. This is consistent with a burst of 12 three-image jobs entering a worker limited to two concurrent jobs. Encoding p95 stayed at 229 ms, while queue wait rose to 1,164 ms. This is an inference from one local run; repeat runs are needed before using it for sizing.

## Reproduce

Build and start a release API and worker against an isolated PostgreSQL database, set the owner password, then pass their process IDs so the wrapper can sample memory:

```powershell
$env:TASKHARBOR_OWNER_PASSWORD = "choose-a-local-password-with-12-or-more-bytes"
$env:BENCHMARK_BUILD_PROFILE = "cargo release"
$env:BENCHMARK_DATABASE_VERSION = "PostgreSQL 18.6"
.\scripts\benchmark.ps1 `
  -ApiUrl "http://127.0.0.1:3000" `
  -Jobs 12 `
  -SubmitConcurrency 4 `
  -WorkerConcurrency 2 `
  -ApiProcessId $apiPid `
  -WorkerProcessId @($workerPid)
```

The machine-readable report is written under ignored `var/benchmarks/` by default. The wrapper records separate API, queue, encoding, attempt, end-to-end, memory, and failure measurements.
